本ファイルは二部構成とする。

## 共通前提

| 項目 | 値 |
| --- | --- |
| 配置 | リポジトリ直下 `e2e/`（通常の `packages/*/…_test` とは分離） |
| 言語 | **Go（`packages/go`）と JS（`packages/js`）の両方**必須。片方のみでは受け入れない |
| S3 実体 | Docker 上の **RustFS**（MinIO 不使用） |
| Local 実体 | Docker 内の **POSIX ボリューム**上の Local Adapter（ホスト `TempDir` のみは不可） |
| モード | **no-DB** のみ（DB 経路は既存単体で担保） |
| 入口 | Go: `core.New` → `Store` / `Get` / `Delete` / `PresignGet`。JS: `createMedian` → `store` / `get` / `delete` / `presignGet` |
| 通常 CI | [`ci.yml`](../../.github/workflows/ci.yml) には**含めない** |
| 手動実行 | ローカル任意 + GitHub Actions `workflow_dispatch`（[`e2e.yml`](../../.github/workflows/e2e.yml) 予定） |
| 依存 | Docker Compose、RustFS イメージ（実装時にタグ / digest を pin）、Go toolchain、Node 24+ |

### 実装固定デフォルト（E2E 環境）

| 項目 | 値 |
| --- | --- |
| RustFS S3 API | Compose サービス名経由（例: `http://rustfs:9000`）、path-style |
| 資格情報 / バケット | テスト専用の固定値（compose / `.env.example`） |
| Presign GET TTL | 出荷デフォルト（1 時間）でよい。短縮 TTL の網羅はしない |
| フィクスチャ | 小さなバイナリ（数 KB 程度の固定バイト列）。画像パイプライン・SVG・PDF は対象外 |

Store 返却の期待フィールドは出荷契約どおり（no-DB 時は `id` / 寸法 / variants 省略可）。`path` / `mime` / `size` / `hash` / `storageKey` は必須確認。

# 第1部: 実装テスト

ハーネス・起動・ランナーの振る舞い。見出しはロジック（またはコマンド）単位。

## Compose / 起動

### compose up（RustFS + POSIX ボリューム）

- RustFS コンテナと Local 用名前付きボリュームを起動する
- ヘルスチェック通過後に S3 API へ到達できる状態にする
- テスト用バケットが利用可能である（init またはテスト setup で作成）

#### テスト：正常系

- `docker compose up`（または同等）で RustFS が healthy になる
- S3 API ポートへ TCP / HTTP ヘルスが通る
- Local 用ボリュームが runner コンテナから読み書きできるパスとしてマウントされる
- テスト用バケットが存在する（または CreateBucket 後に利用できる）

#### テスト: 異常系

- RustFS が起動しない／ヘルス失敗のとき、E2E ランナーは失敗終了する（偽成功しない）
- 必須環境変数（endpoint・資格情報・バケット・Local ルート）欠落時はランナーが明確に失敗する

### compose down / クリーンアップ

- 実行後にコンテナと一時状態を片付けられる

#### テスト：正常系

- `compose down`（または Workflow の teardown）でサービスが停止する
- 再実行時に前回のオブジェクト残骸に依存しない（バケット空、または一意プレフィックス）

#### テスト: 異常系

- teardown 失敗はログに残る（サイレント無視しない）。ただし本マイルストーンではリトライ網羅は必須にしない

---

## Go E2E ランナー

### e2e/go 実行

- Compose 起動済みの RustFS / POSIX ボリュームに対し、Go のクリティカルシナリオを実行する
- 通常の `go test ./...`（packages/go）とは別エントリ（build tag または `e2e/go` パッケージ）

#### テスト：正常系

- 環境が揃っているとき、Local 軸シナリオ（後述 L1）が成功する
- 同条件で RustFS 軸シナリオ（後述 S1）が成功する
- 終了コード 0

#### テスト: 異常系

- RustFS 未起動・バケット無し・資格情報誤りで S1 が失敗し、非 0 終了する
- Local ルートが未マウント／書き込み不可のとき L1 が失敗し、非 0 終了する

---

## JS E2E ランナー

### e2e/js 実行

- Go と**同一シナリオ**を TypeScript（`@b4moss/median`）で実行する
- 通常の `npm test`（packages/js）とは別エントリ（例: `MEDIAN_E2E=1` または `e2e/js`）

#### テスト：正常系

- Local 軸 L1 が成功する
- RustFS 軸 S1 が成功する
- 終了コード 0

#### テスト: 異常系

- Go ランナーと同様、接続・資格情報・Local ルート不正で非 0 終了する
- Go のみ成功・JS 失敗（またはその逆）の状態は**マイルストーン未達**（両方必須）

---

## GitHub Actions Workflow

### workflow_dispatch（e2e.yml）

- 手動実行専用の Workflow を提供する
- 通常の PR / push では起動しない

#### テスト：正常系

- Actions 上で手動実行すると Compose → Go E2E → JS E2E の順（または同等の直列／明確な依存）で走る
- すべて成功時にジョブ成功となる

#### テスト: 異常系

- `ci.yml` の path filter / jobs に E2E が混入していない（docs のみ PR で E2E が必須ゲートにならない）
- Go または JS のいずれか失敗で Workflow 全体が失敗する

# 第2部: E2E シナリオ（別枠）

利用者（ライブラリ呼び出し側）のクリティカル経路。  
**実装テストの見出し形式とは分け**、シナリオ ID・前提・手順・期待結果で記述する。

Go / JS は**同じシナリオ ID・同じ手順・同じ期待**を満たすこと。差異は言語 API 名のみ（`Store`/`store` など）。

## 共通（全シナリオ）

| 項目 | 内容 |
| --- | --- |
| DB | 使わない（no-DB） |
| 入力 | 固定の小さなバイト列（例: `hello-median-e2e`）と宣言 MIME（例: `application/octet-stream`） |
| 検証 | 返却メタの `size` / `hash`（SHA-256）と、Get した本文バイトが入力と一致すること |
| 言語 | 各シナリオを Go と JS の両方で実施 |

---

## シナリオ L1 — Local: Store → Get → Delete

**目的:** Docker 内 POSIX 上の Local Adapter で、保存・取得・削除の往復が成立すること。

**前提:**

- runner コンテナから Local ルート（Compose ボリューム）へ書き込める
- median を Local storage key のみ（または defaultKey = local）で初期化済み

**手順:**

1. `Store`（または `store`）でフィクスチャを保存する
2. 返却の `path` / `storageKey` / `size` / `hash` を記録する
3. 同じキーで `Get`（body 付き）する
4. `Delete` する
5. 再度 `Get` する

**期待結果:**

| ステップ | 期待 |
| --- | --- |
| 1 | エラーなく完了。`size` は入力長、`hash` は入力の SHA-256 hex |
| 3 | 本文バイトが入力と一致。メタの `hash` / `size` が Store 時と一致 |
| 4 | エラーなく完了 |
| 5 | not-found（出荷契約のエラー種別に相当） |

**対象外:** パストラバーサル拒否の網羅、複数 storage key 切替、DB あり Delete-by-id

---

## シナリオ S1 — RustFS: Store → Get → PresignGet → Delete

**目的:** Docker 上 RustFS に対し、オブジェクトの往復と署名付き GET が成立すること。

**前提:**

- RustFS が healthy
- テスト用バケットが利用可能
- median を S3 storage key（Endpoint / path-style / 資格情報 / Bucket）で初期化済み

**手順:**

1. `Store` でフィクスチャを保存する
2. 返却の `path` / `storageKey` / `size` / `hash` を記録する
3. 同じキーで `Get`（body 付き）する
4. `PresignGet` で URL を取得する
5. その URL に対し HTTP GET する（署名検証を実リクエストで確認）
6. `Delete` する
7. 再度 `Get` する

**期待結果:**

| ステップ | 期待 |
| --- | --- |
| 1 | エラーなく完了。`size` / `hash` が入力と整合 |
| 3 | 本文バイトが入力と一致 |
| 4 | HTTP(S) URL 文字列が得られる |
| 5 | ステータス成功。レスポンス本文が入力バイトと一致 |
| 6 | エラーなく完了 |
| 7 | not-found |

**対象外:** Presign TTL 境界、Local に対する Presign（`ErrNotS3` 等は単体の範囲）、マルチパート・巨大オブジェクト

---

## シナリオ行列（受け入れの見方）

| シナリオ | Go | JS | 必須 |
| --- | --- | --- | --- |
| L1 Local | 通ること | 通ること | はい |
| S1 RustFS | 通ること | 通ること | はい |

4 セルすべて成功で本マイルストーンのシナリオ受け入れとする。
